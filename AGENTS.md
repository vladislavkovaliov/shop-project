# shop-project — monorepo

Содержит два подпроекта:
- `shop-ui-angular/` — Angular 21.2 frontend
- `shop-api-golang/` — Go backend (SQL workshop)

---

## shop-ui-angular

Angular 21.2 CLI scaffold — standalone components, SSR, Tailwind v4, Vitest.

### Commands

| Action | Command |
|--------|---------|
| Dev server | `ng serve` (port 4200) |
| Build (SSR) | `ng build` → `dist/shop-ui-angular/{browser,server}/` |
| SSR server | `node dist/shop-ui-angular/server/server.mjs` (port 4000) |
| Test (Vitest) | `ng test` |
| Format | `npx prettier --write .` |

### Framework & quirks

- **Standalone components only** — no `NgModule`. Generated via `ng generate component`.
- **SSR** via `@angular/ssr` + Express (`src/server.ts`). All routes prerendered by default (`RenderMode.Prerender`).
- **Tailwind CSS v4** via PostCSS plugin (`@tailwindcss/postcss`). Global import in `src/styles.css`: `@import 'tailwindcss'`. No `tailwind.config.*` — use inline `@theme` directives.
- **Vitest** (not Karma/Jasmine). Test runner configured by `@angular/build:unit-test` builder — no `vitest.config.ts`. Globals (`describe`, `it`, `expect`) available without imports (`vitest/globals` in `tsconfig.spec.json`).
- **Prettier** only formatter — `printWidth: 100`, `singleQuote`, `angular` parser for HTML (`npx prettier --write .`). No ESLint.
- **Strict TypeScript** (`strict`, `strictTemplates`, `strictInjectionParameters`, `strictInputAccessModifiers` all on).
- **No CI/CD**, no git hooks, no task runner config found.

## shop-api-golang

Go educational backend for a SQL workshop. Module name: `shop-api` (Go 1.25).

### Project structure

```
shop-api-golang/
  cmd/api/main.go              — entrypoint
  internal/config/config.go    — env-based config (godotenv)
  domain/product/              — Product entity + Repository interface
  repository/product/          — repository implementation (empty)
  service/product/             — business logic (empty stub)
  http/handlers/product.go     — Gin handler (imports service, not wired)
  http/dto/product.go          — response DTO
  docs/                        — swaggo generated (regenerated by Air)
  .air.toml                    — hot-reload config
```

### Key conventions

- **Architecture**: domain → repository → service → handler (clean layers, DIP via interfaces in domain)
- **Repository interface** lives in `domain/product/repository.go`, impl goes in `repository/product/`
- **Package naming**: service package is `service/product/` (package `product`), handler package is `http/handlers/` (package `handlers`)
- **Domain fields are Unexported lowercase** — intentional (project style); serialization uses explicit mapping in DTOs
- **DTO fields must be Exported** to work with `encoding/json` — current `ProductResponse` has lowercase fields, which is a bug (json tags won't help if field is unexported)

### Commands

| Action | Command |
|--------|---------|
| Run with hot-reload | `air` (from `shop-api-golang/`) |
| Manual build | `go build -o ./tmp/main ./cmd/api/main.go` |
| Run directly | `go run ./cmd/api/main.go` |
| Regenerate swagger | `swag init -g ./cmd/api/main.go` |
| Run tests | `go test ./...` |

### Database

- Default URL: `postgres://postgres:postgres@localhost:55000/shop`
- Config via env vars: `PORT`, `DATABASE_URL` (loaded from `.env` if present)
- No Docker setup in repo — Postgres expected externally (see `scripts/` for SQL)
